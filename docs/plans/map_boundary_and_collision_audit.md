## 一、 发现的问题分类与根因分析

在本次排查与全量扫描中，共归纳出三大共性地图暗病体系：

### 1. 类型 A：通行度解包偏差与黑边虚空漫游 (Passability Offset & Open Void)
- **底层根因**：
  - RMXP 的 `@passages` 是结构化 Table，前 20 字节为头部元数据，实际图块标志位从偏移量 20 起排列。构建脚本曾因头部偏移取值错误，将图层 0 上的水体、悬崖或树林判定为可通过（0）。
  - 在裁剪式室内地图（如装备店 MT8、酒馆 MT9、公会回廊 MT10、法芙娜寓所 MT11）中，房间外围黑色空地为 `tid == 0`。旧脚本遇到 `tid == 0` 时直接 `continue` 跳过，导致外围空地默认被置为平地 `0`。
- **具体表现**：
  - **MT15（密林深径）**：顶部边缘 `y=0` 树冠无空气墙阻挡，玩家强行北行会导致半身截断穿模。
  - **MT16（运河支流前哨）**：水体阻挡漏判，玩家在 `y=0~7` 的大水面上如履平地。
  - **MT8 / MT9 / MT10 / MT11 / MT7**：室内墙外大片黑色虚空完全可走，玩家可走出房间漫游虚空。
  - **MT6（厄泽城 75x75）**：外围边缘存在 191 处开孔，玩家走到边缘可走出城外。

### 2. 类型 B：传送落脚点堵塞与卡死 (Spawn Point Trapped / Blocked)
- **底层根因**：
  - 双向传送配置时，只校验了单向通畅度，未反向验证返程目标点是否与地图现有图元重叠。
- **具体表现**：
  - **MT7 (23, 31)**：从 MT10 返回 MT7 时，落点被配置在空气墙（17）上，玩家落地即卡死。
  - **MT10 (16, 7)**：从 MT11 返回 MT10 时，落点被配置在空气墙（17）上，玩家落地即卡死。
  - **MT15 (7, 1)**：从 MT14 南出口返回 MT15 时，落点正对着树精怪物（210），产生踩怪。
  - **MT4 (13, 7)**：从 MT5 西门返回 MT4 时，落点正对着骷髅卫士（214），产生踩怪。
  - **MT3 (13, 5)**：从 MT4 西门返回 MT3 时，落点正对着倍荷玛（202），产生踩怪。

### 3. 类型 C：未开放支线在边界留下裸露断头路 (Unconnected Branch Outlets)
- **底层根因**：
  - 原版 RMXP 存在分支地图，魔塔未移植该支线时，边缘图块保持原样平地（0），且缺乏 `changeFloor` 或空气墙阻隔。
- **具体表现**：
  - **MT3 (0, 3)**：原版通往 Map015（哥布林洞穴），魔塔中裸露在西边界，无阻挡且半身穿模。
  - **MT14 (0, 8)**：原版通往 Map022（姆伊森运河下游激流），魔塔中裸露在西边界，无阻挡。
  - **MT1 (2, 14)**：原版通往 Map049（森林深处），魔塔中底部开孔。

## 二、 修复方案与工程落地

针对上述三类问题，编写了工业化修复工具 [`tools/fix_all_maps_collision_and_boundaries.py`](file:///Users/zt-lin/Document/永不复还/移植包-永不复还转mota-js/tools/fix_all_maps_collision_and_boundaries.py)：

1. **RMXP 权威碰撞提取 (`tools/rmxp_indoor_collisions.json`)**：
   - 严格根据 RMXP 引擎内核 `Game_Map.passable?` 四方向掩码与优先级判定算法，对室内地图 `MT7`, `MT8`, `MT9`, `MT10`, `MT11` 重新生成了 100% 严密的真实碰撞矩阵；
   - 彻底将房间外围黑色虚空封死为空气墙（17），柜台、桌椅、实心墙壁 100% 对齐原版。
2. **安全落点与图元重置**：
   - **MT7**：修复返回落点为 `(22, 30)`，并将守卫放行逻辑绑定至 `eachArrive` 与 NPC 对话中，任务完成后自动 `core.removeBlock(22, 30)`，彻底避免卡死。
   - **MT10**：清空 `(16, 7)` 地面阻挡为 0，门置于 `(16, 6)`，玩家可站在 `(16, 7)` 正常交互或安全返程。
   - **MT15**：将守护怪 210 安全平移至 `(5, 1)`，`(7, 1)` 保持平地净空。
   - **MT4**：将守护怪 214 安全平移至 `(13, 6)`，`(13, 7)` 保持平地净空。
   - **MT3**：将守护怪 202 安全平移至 `(12, 5)`，`(13, 5)` 保持平地净空。
3. **未开放支线与大地图全周密封**：
   - **MT1 (2, 14)**：铺设空气墙 17，底部森林全线封闭。
   - **MT3 (0, 3)**：铺设空气墙 17，并配置塌方封路提示路牌。
   - **MT14 (0, 8)**：铺设空气墙 17，并配置激流险滩提示。
   - **MT5**：顶部（y=0）、底部（y=14）及东侧城墙全线铺设空气墙 17，仅保留城门 `(14, 7)` 进出。
   - **MT6**：全周 75x75 最外围边缘（`x=0, 74`, `y=0, 74`）铺设空气墙 17，彻底杜绝走脱出城。

## 三、 自动化测试体系与防护网

为确保后续新增地图或修改时绝不发生穿模与死循环回归，构建了双层自动化防御网：

### 1. 静态拓扑与边界完整性审计 (`tools/test_map_integrity.py`)
- **包含 186 项全量自动检查**：
  - 楼层文件完整性与结构校验；
  - 所有传送目标楼层存在性与坐标越界断言；
  - 传送落点净空安全性（断言 tile 必须为 0，严禁 17 空气墙，严禁 >=200 怪物贴脸）；
  - 传送落点防对撞死循环断言；
  - **BFS 洪水填充边界穿模检测**：从全图所有可能入口/落脚点做连通性扩散，断言可到达区域触及地图边缘的格子必须具备有效的出口定义，0 裸露开孔，0 穿模。

### 2. 动态端到端自动化验收套件 (`tools/run_full_game_test.py`)
- 将 `test_map_integrity.py` 纳入第一阶段前置校验（阶段 -1），任何地图配置异常在测试启动 0.1s 内即刻阻断；
- 在原有 42 项真实浏览器端到端测试基础上扩充至 **48 项全量 E2E 真实操作实测**：
  - 包含 MT1 底部防穿模实测；
  - MT3 西侧防穿模实测；
  - MT15 顶部树林防穿模实测；
  - MT16 水面防踩水实测；
  - MT14 激流边缘防穿模实测；
  - MT11 -> MT10 -> MT7 全双向返程安全通行实测；
  - 终局 32 句主线剧情与全阶段战斗。
